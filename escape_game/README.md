# 出口断电 / Backrooms Escape

单人桌面第一人称原型。原生 JavaScript、WebGL2、GLSL，Node 后端，无第三方运行依赖。

## 启动

需要 Node.js **20.12 或更新版本**。在任意目录运行一条命令：

```sh
node /Users/rzzz/Desktop/Workspace/Projects/backrooms/escape_game/server.js
```

打开 **http://localhost:3037**。也可以在本目录运行 `npm start`，不需要先安装依赖。
服务只监听本机 `127.0.0.1`，不占用 VR 服务的 2026 端口。若端口被占用，用 `PORT=3038 node server.js`。

## 操作与玩法

| 操作 | 功能 |
| --- | --- |
| 点击“进入设施”或画面 | 请求 Pointer Lock |
| WASD / 鼠标 | 移动 / 观察 |
| Shift | 快跑，会产生可被附近怪物听见的脚步 |
| E | 操作附近的门、电源开关或出口 |
| T | 打开 / 关闭对话；输入框中 Esc 关闭对话 |
| Esc | 释放鼠标并暂停 |
| M | 收起 / 显示线路图 |
| 重新开始 | 重置本局，包括门、聊天和待处理 AI 请求 |

浏览器拒绝 Pointer Lock 时，可以**按住画面拖动观察**。对话期间游戏继续，键盘输入不会同时移动玩家。
切换标签页或窗口失去焦点会暂停，重新进入需要点击继续。

唯一任务：**前往泵房恢复供电，再回黄色柱廊西墙的出口按 E 逃生。**

```text
黄色柱廊 ───── 储物间
   │         ╱   │
   │       ╱     │
   泳池 ─────── 泵房
```

四个区域在同一个连续空间，五条连接廊均可双向通行。储物间有货架遮挡，泳池需走池边走道，泵房设备也需要绕行。
连接门初始打开；可以关门阻挡视线和移动，但怪物能停下约 1.8 秒开门。门口有人时不能把门关在人身上。
玩家步行速度 3.1、快跑 4.4；怪物搜索速度 2.0、追逐 3.65。单位为米/秒。被接触即失败，没有战斗或背包。

供电声沿通路传播，怪物听见后有 4 秒反应时间。利用环路离开，注意实时位置播报。自由聊天完全可选。

## DeepSeek 配置

默认 `https://api.deepseek.com` / `deepseek-flash` / `thinking: disabled`。
设置进程环境变量，或把 `.env.example` 复制为本目录 `.env` 后填写：

```dotenv
PORT=3037
AI_BASE_URL=https://api.deepseek.com
AI_MODEL=deepseek-flash
DEEPSEEK_API_KEY=你的密钥
```

兼容已有变量名 `OPENAI_API_KEY`。进程环境覆盖本目录 `.env` 的同名配置；优先选择 `DEEPSEEK_API_KEY`。
二者均缺失时，仅在本机从下面文件读取密钥：

```text
/Users/rzzz/Desktop/Workspace/Affair/NYU/26Fall/VR/Keyu-VR-2026/.env
```

可通过 `VR_ENV_PATH` 指定另一份本机参考配置。不会修改 VR 项目。
密钥只在后端读取，`.env` 已忽略，静态服务只提供列出的游戏文件，不提供后端、测试文件或配置。
游戏仅向模型发送虚构世界的观察、行动和少量对话，不发送本地文件内容。

`AI_DISABLED=1 node server.js` 可运行纯基础搜索模式。连接失败、超时、错误工具或冷却期间，实时移动和胜负逻辑继续工作。
右下角明确标出“LLM 控制”或“基础行为”，配置成功不等于模型决策已执行。

AI 只选择 `moveToRegion`、`searchRegion`、`investigateSound`、`guardExit` 四种工具，返回值会经过后端校验和游戏可达性检查。
追逐优先于模型建议。模型不会接收玩家实时位置；只会接收最近目击和沿实际通路传到怪物处的声音。
位置播报每次直接读取怪物的真实区域、廊道和行动；AI 对白不能改写它。
事件触发请求，前端至少间隔 10 秒，失败后退避 20 秒，后端有并发及频率限制。等待时继续已有行动。
重开会中止请求并更换局编号，旧回答即使随后到达也会被丢弃。

工具调用协议参考 [DeepSeek 官方文档](https://api-docs.deepseek.com/guides/tool_calls/)。

## 实现与检查

`world.js` 描述区域、通道、墙、门和遮挡，渲染、碰撞、视线及网格寻路均使用这份数据。
`simulation.js` 处理实时玩法，`ai.js` 管理事件请求和旧局隔离，`server.js` 负责静态服务和受限工具调用。
`renderer.js` 与独立 GLSL 保留黄色壁纸、柱阵、轻微灯光变化，以及泳池瓷砖、拱门和水面。
水面采用平面反射缓冲、波纹法线、Snell 折射、Fresnel 混合与水下吸收；反射降低分辨率以控制开销。

视觉思路改编自 `../level0/level0.html` 和 `../swimming_pool/swimming_pool.html`；控制与 AI 接口参考所给现有代码。
原有场景、学习副本和 VR 课程项目均未修改。

```sh
npm test
```

测试涵盖通道拓扑、碰撞、真实通关、追逐失败、信息边界、开门延迟、声音范围、工具校验、失败和重开隔离。
浏览器操作与证据边界见 [验收记录](VALIDATION.md)。`?test=1` 仅向画布的 `data-inspection` 属性输出本局观察数据，便于浏览器验收；没有传送或无敌入口。

限制：固定小地图，简单程序化怪物与环境音；水面是浅波纹近似，不含游泳、复杂阴影或攻击动画。
当前平衡允许快跑拉开距离，尚未做多名玩家的长期难度测试。桌面浏览器版本不提供触屏或 WebXR 操作。
