# Backrooms Escape 实现说明

这是一份对当前代码的说明。游戏在浏览器内维护世界和实时玩法，Node 服务转发 DeepSeek 请求。
模型选择搜索策略，游戏执行移动、感知、追逐和胜负判定。

## 1. 文件与数据流

| 文件 | 职责 | 建议先看的入口 |
| --- | --- | --- |
| `index.html`、`style.css` | 开始页、任务、地图、对话、暂停和结果界面 | `overlay`、`radio` |
| `game.js` | 输入、主循环、界面更新、声音与重新开始 | `frame()`、`hud()`、`restart()` |
| `world.js` | 共享地图、障碍、门、碰撞、视线和寻路 | `createWorld()`、`move()`、`findPath()` |
| `simulation.js` | 玩家与怪物状态、声音事件、任务和胜负 | `Game.step()`、`perceive()`、`applyDecision()` |
| `renderer.js` | 三角形网格、WebGL 资源、标识纹理、反射缓冲 | `build()`、`render()` |
| `scene.vert`、`scene.frag` | 相机投影、环境材质和照明 | 两个 `main()` |
| `water.frag` | 波纹、反射、折射与吸收 | `waterNormal()`、`main()` |
| `ai.js` | 事件触发请求、限频、过期回答和降级 | `Director.tick()`、`request()` |
| `server.js` | 本机静态服务、密钥配置与工具调用 | `configuration()`、`createServer()` |
| `tests/` | 独立于画面的玩法测试与后端协议测试 | `npm test` |

一帧内的主要顺序是：

```text
键盘输入 → Game.step(dt, input) → 更新玩家、感知、怪物、胜负
                               ↓ 产生事件
                         Director.tick() → 异步请求后端 → DeepSeek
                               ↑                            ↓
                         Game.applyDecision() ← 校验后的工具参数

当前 Game 状态 → Renderer.render() → WebGL 画面
              → hud() → 任务、交互提示、真实位置与线路图
```

`Game` 不依赖 DOM 或 WebGL，因此可以单独测试玩法。浏览器里的 `game.js` 把输入、模拟、渲染和界面连接起来。

## 2. 地图与共享几何

世界是连续空间，地面按 **2 × 2** 的格子组织。`regions` 定义四个房间的范围、名称和中心点，`links` 定义五条双向走廊及门的位置。
区域 ID 始终是 `yellow`、`storage`、`pool`、`pump`，显示名称为英文。

`createWorld()` 先填充房间与走廊格子，再沿没有相邻格子的边缘生成墙体，最后加入柱子、货架、泵房设备和泳池边的拱柱。

核心数据是：

```js
world = {
   cells: Map, // 可用格子，以及它属于哪个区域或走廊
   solids: [], // x、z、w、d、h 描述的障碍
   doors: []   // 位置、方向、开关状态、对应连接
};
```

渲染器读取这些障碍生成网格；碰撞与视线也读取同一份数据。门的绘制与阻挡范围都来自 `doorBox()`。
水池在移动规则里是不能踏入的坑，玩家沿周边通行。拱门的顶部曲面是装饰网格，高于玩家通行高度；拱柱参与碰撞。

`locate()` 根据真实坐标查找区域或连接廊，再用相对房间中心的方向生成 `Pool · east side` 这样的名称。
这里的 north/south 对应地图的 z 方向，并非额外维护的位置状态。

## 3. 玩家移动、相机与碰撞

`game.js` 把按下的键存在 `Set` 中，每帧转成 forward、right 和 sprint。鼠标改变水平角 `yaw` 与俯仰角 `pitch`。
WASD 方向根据 yaw 转到世界坐标，再归一化，因此同时按 W 和 D 不会移动得更快。

```text
本帧位移 = 世界空间单位方向 × 速度 × dt
```

步行速度为 3.1，快跑为 4.4。`dt` 最多取 0.05 秒，避免切回页面或卡顿后出现一次很大的模拟位移。

碰撞把角色视为地面上的圆，把障碍视为轴对齐矩形。`canStand()` 求圆心到矩形最近点的距离，距离小于角色半径就阻挡。
`move()` 进一步把位移切成不超过 0.08 的小步，每步分别尝试 x 和 z 方向：既减少穿墙，也允许贴墙滑动。
玩家和怪物使用同一个移动函数。

Pointer Lock 下读取鼠标相对位移；浏览器拒绝锁定时提供拖动观察。Esc、失焦或隐藏页面会暂停；聊天时游戏继续，但不向模拟传入移动输入。

## 4. WebGL 渲染与环境材质

这里使用普通三角形光栅化。`Mesh.box()` 把长方体拆成六个面，每面两个三角形；顶点包含位置、法线、材质编号和 UV，共 9 个 float。

静态房间网格只构建和上传一次。门、怪物及电源指示灯构成动态网格，每帧重新上传。水面使用单独网格与着色器。
所有物体开启深度测试，近处表面会遮挡远处表面。

`scene.vert` 从 yaw、pitch 构造 forward、right、up，把世界坐标投影到相机坐标，再输出透视裁剪坐标。
相机眼高固定为 1.65，没有跳跃或完整刚体物理。

`scene.frag` 根据材质编号和世界坐标生成外观：

- 黄色墙用重复条纹与微弱颗粒模拟壁纸，柱子沿用同一材质。
- 储物间与泵房采用较暗的条纹材质。
- 泳池用 `fract()` 和 `smoothstep()` 划出瓷砖与接缝。
- 天花板荧光灯直接输出发光颜色，叠加很小的正弦亮度变化。
- 普通表面使用环境项，加附近九个规则排列的灯光位置的漫反射与距离衰减。
- 最后加入轻微距离雾并做 gamma 校正。

灯光没有实时阴影，明暗变化属于程序化近似。场景门牌由 Canvas 绘制成纹理图集，再贴到小矩形网格上。

## 5. 泳池、水面反射与折射

水面分两次绘制：

1. 将场景关于水面 `y = -0.1` 镜像，画入离屏反射纹理。
2. 正常绘制场景，再绘制水面，读取反射纹理与程序化水底颜色。

反射缓冲宽高各为主画面的 60%，像素数约为 36%。主画面本身也限制渲染分辨率，降低高像素密度屏幕的负担。

`waves()` 叠加两个随时间移动的正弦波。`waterNormal()` 对波高做中心差分，把高度变化转换为法线：

```text
n = normalize(-∂h/∂x, 1, -∂h/∂z)
```

这个法线扰动反射纹理的采样位置，并参与折射计算。水面网格本身仍是平面。
折射使用 GLSL 的 `refract(ray, normal, 1 / 1.333)`，再与约 1.3 深度的水底相交，得到水底瓷砖的取样位置。
水下颜色按 `exp(-吸收系数 × 路程)` 衰减，红色吸收更多，形成青绿色水体。

Fresnel 项使用 Schlick 近似：越贴近水面观察，反射比例越大；越垂直观察，越容易看见水底。
水底亮纹由正弦函数构造，属于焦散的视觉近似。折射没有再次追踪完整场景，也没有真实流体模拟。

## 6. 交互、声音和胜负

`interaction()` 筛选距离玩家小于 2.0 且视线可达的门、开关和出口，选最近一个显示 `[E]` 提示。
操作门时检查门口是否有人，避免把关闭的门直接生成在角色身上。

供电状态是 `game.powered`：初始为 false，操作泵房开关后变为 true。界面随即切换为返回出口的任务；供电后在出口按 E 设置 `result = 'won'`。
怪物与玩家距离小于 0.66，且二者之间没有视线障碍时，设置 `result = 'lost'`。

游戏内声音是带位置的事件，和玩家听到的音效分开处理：

| 事件 | 传播范围 | 非追逐时的反应延迟 |
| --- | --- | --- |
| 快跑脚步，每 3 秒最多一次 | 15 | 0.6 秒 |
| 开关门 | 24 | 0.6 秒 |
| 泵房启动 | 120 | 4 秒 |

`noise()` 计算怪物到声源的可行路径长度，每经过一扇关闭的门再加 6；超过范围就不生成“听见”的事件。
这是沿通道传播的简化声学模型。可听见的声源会提供准确事件坐标，未听见的事件不会进入模型的声音列表。

浏览器的环境声是一个低音量 60 Hz 振荡器，操作音效也是短振荡音；没有使用空间音频定位。

## 7. 怪物状态机与寻路

怪物保存当前位置、朝向、行动、路径、最后目击信息和等待时间。主要行动为：

| mode | 执行行为 |
| --- | --- |
| `travel` | 沿路径前往区域 |
| `search` | 检查区域内的可站立点，到点后停留转向 |
| `investigate` | 前往听见的声音或最后目击位置 |
| `chase` | 持续追向最近看见的玩家位置 |
| `guard` | 前往出口附近，停留后继续巡查 |

`findPath()` 在格子中心构成的四邻接图上执行 BFS，用 `previous` 记录前驱并重建路径。
起点和终点连接实际角色坐标；每条相邻节点之间的路段也经过 `canWalk()` 检查，避免端点可站立、途中却有障碍。
这里的路径最短是按格子步数计算，没有 A* 启发式或门等待时间的代价优化。

怪物规划时可以把关闭的门视为将来能打开的连接；实际移动仍会被门挡住。接近路径上的关闭门后等待 1.8 秒，打开后继续。
搜索/调查移动速度为 2.0，追逐为 3.65。

`perceive()` 约每 0.12 秒检查一次距离、朝向和视线。视距为 19，方向条件为 `cos(angle - yaw) > -0.15`；3.5 内放宽朝向要求，但仍不能隔墙发现玩家。
`visible()` 沿二维连线每隔约 0.12 取样，检查墙、足够高的障碍和关闭的门。

看见玩家时立即进入追逐并更新 `lastKnown`。丢失视线后该位置冻结，超过 1.6 秒转为调查最后目击位置。
追逐中由 `canWalk()` 检查整条直线路段能否容纳角色，通过才直接移动，否则每 0.7 秒重新规划路径。
视线与通行条件分开：能隔着水池看见玩家，也必须沿池边绕行。重复目击更新最后已知位置，保留当前绕行路径。
没有传送或持续读取隐藏玩家坐标的追踪机制。

基础行为会持续接手到达、等待和巡查等流程，也在模型离线时独立运行。没有线索时，按 Pool → Storage → Pump Room → Yellow Colonnade 巡查。
局部搜索从较远的可站立点里选择一个，没有维护“每个角落是否已经搜过”的覆盖记录。

## 8. DeepSeek 的输入、工具与调用时机

`snapshot()` 发给模型的状态包括：

- 地图连接、怪物真实位置、当前行动与目标区域。
- 最后实际看见的玩家位置、40 秒内仍有效的可听声音。
- 门的开关与出口供电状态。
- 最近 8 个事件；`Director` 另附最近 6 条对话。

其中没有玩家实时位置字段。门与供电状态是提供给模型的全局设施信息，玩家位置则受视线和声音信息约束。
玩家聊天是可能的诱导，提示词要求模型结合观察自行判断。

模型只能返回以下工具之一，并附带一句简短英文对白：

| 工具 | 参数 | 游戏中的结果 |
| --- | --- | --- |
| `moveToRegion` | `region`、`line` | 向该区域中心规划路线 |
| `searchRegion` | `region`、`line` | 在当前区域选择检查点，或先前往目标区域 |
| `investigateSound` | `soundId`、`line` | 前往仍有效的已听声源 |
| `guardExit` | `line` | 供电后前往出口附近截路 |

后端检查工具名、必需参数、区域、声音 ID 与供电前提；`applyDecision()` 再检查当前是否可执行、目标是否可达。
模型输出不作为 JavaScript 执行。

开始、进入区域、听见声音、丢失玩家、收到消息或巡查空闲会排队触发请求。前端至少间隔 10 秒，只允许一个待处理请求；追逐期间不发起请求。
请求在后台等待，怪物继续已有行动。

`server.js` 使用 Node 内置 HTTP 服务与 `fetch()`，请求 `/chat/completions`，设置 `thinking: { type: 'disabled' }` 与 `tool_choice: 'required'`。
默认模型和地址、密钥优先级以及启动命令见 [README](README.md)。密钥只由后端读取。

## 9. 过期回答、降级与重新开始

回答可能在世界已经变化后才到达，因此有两层检查：

- **generation**：重开或结束时递增，并中止待处理请求。旧局回答即使随后到达，也不能修改新局。
- **revision**：出现声音、目击、丢失目标或新消息时递增。回答基于旧观察时被丢弃，稍后重新请求。

此外，`applyDecision()` 拒绝打断追逐和声源反应等待期。前端超时为 16 秒，后端上游超时为 14 秒；失败后前端等待 20 秒再尝试。
后端另有一次请求并发限制和 4 秒冷却。

缺少密钥、禁用 AI、网络失败或无效工具都会显示英文基础搜索状态。`LLM control / … Decision applied` 表示真实模型决策已被游戏采纳；仅配置成功仍显示等待决策。

重开创建新的 `Game`，恢复玩家、怪物、门、供电、计时、事件和历史，同时清空界面聊天、键盘输入与 `Director` 的对话记忆。
地图布局固定，因此渲染器继续复用同一份静态网格，动态状态从新局读取。

## 10. 位置播报、英文界面与验证范围

`broadcast()` 每次从实际怪物坐标调用 `locate()`，再附加行动、目的区域或开门状态。HUD 约每 80 毫秒刷新。
位置栏与对白日志是独立元素，模型对白无法覆盖位置栏。

英文文字直接写在原有界面、区域名称、交互提示、纹理标识和错误状态中，没有引入多语言框架。
模型的系统提示词和工具说明也使用英文，要求玩家使用其他语言时仍输出英文对白；玩家自己的输入按原文显示。
线路图使用较短的大写区域标识，避免英文全名超出小方框。

`npm test` 检查地图连接、碰撞、任务通关、追逐失败、信息边界、门延迟、声音范围、工具校验和旧局回答隔离。
后端测试使用模拟上游，只证明协议与错误处理；真实模型与画面必须另在浏览器中验证。
原型验收记录见 [VALIDATION.md](VALIDATION.md)。

当前限制是固定地图、简单局部搜索、二维视线、近似声学、无阴影照明与平面水面效果。没有长期信念模型、复杂攻击、游泳或 WebXR 支持。
